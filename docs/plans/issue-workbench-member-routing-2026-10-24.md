## 新派工规则顺序

1. 核对 Open、当前负责人、组织成员和仓库权限；保留已有其他负责人，不自动抢单或给 Closed 问题派工。
2. 先按问题实际受影响系统筛选人员。历史对比、仅出现平台关键词不等于受影响证据。未知系统、Linux 或跨平台问题需补充判断；跨平台可拆分责任，不随意选一人承担全部平台。
3. 系统合格候选内，macOS 框架问题优先已确认的架构师；Windows 核心架构/功能方案优先 `whutzefengxie-ops`。
4. 普通问题保留“组员自提优先本人”，但本人必须满足系统条件；其余继续匹配 Feature、分类分工。
5. 同级普通 macOS 候选再按约定比重分配。架构师优先、作者优先、明确 Feature 负责人不混入普通加权样本；Windows 普通候选不虚构额外权重。
6. 手动、自动派工统一校验系统限制，显示推荐与排除理由。重复请求、失败重试不重复计数；写入前重新核对成员、权限和规则。

这收窄了旧“自提优先”的适用范围：不能因为作者是 Mac 成员，就把 Windows 问题派回本人。
